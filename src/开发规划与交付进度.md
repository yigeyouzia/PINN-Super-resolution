# 开发规划与交付进度

| 项目 | 截至本次的实际状态 | 证据与边界 |
| --- | --- | --- |

说明：

- 根 README 与既有实验文档包含不同日期的验证状态；上表补充用户最新反馈，不代表本次已审计 Linux 实验。
- fit RMSE 是训练观测点上的拟合指标，不是独立测试集精度，也不能证明完整三维空间的重建精度。
- 当前公开基线是空间坐标 (x, y, z) 到 (u, v, w, p) 的稳态三维 PINN，没有时间输入与预测窗口。
- 本轮目标是工程可持续开发，不引入新的论文方法或改变原损失定义。

## 2. 重构边界

1. 作者 pinn/、公开数据、作者预训练模型及历史 runs/ 不修改、不覆盖、不移动。
2. 自维护的计算与训练逻辑统一放到 src/pinn_sr/；根 train.py 保留为命令行薄入口。
3. 尽量沿用作者 network.py、pinn.py、pinn_train.py 的分工，同时新增必要的配置、数据、实验与 checkpoint 模块。
4. 首轮保留现有 CLI 参数名称、默认值、项目根目录相对路径语义及运行目录防覆盖规则。
5. 首轮不同时更换网络、损失归约方式、优化器、初始化、物理方程或训练超参数，避免把方法变化混入重构。
6. 训练、推理和绘图分离：加载模型不创建优化器、不触发训练；数值评价不依赖 Mayavi。
7. 不提前建设复杂插件、模型注册中心或配置框架；当前 argparse + JSON 足够，先稳定边界。
8. 后续实现前重新读取当前源码和 Git 状态，保留其他会话的修改；本文的符号清单不是静态覆盖依据。

## 3. 目录结构与实现边界

src/README.md、src/__init__.py 与 pinn_sr 的 config/runtime/data/network/pinn/pinn_train/checkpoint/experiment/metrics/cli 已实现。下图 evaluate.py、evaluation.py、visualization.py 仍为未来计划，不表示已存在。

```text
PINN-Super-resolution/
├── pinn/                         # 作者原文件，只读参考
├── train.py                      # 原命令兼容的训练薄入口
├── evaluate.py                   # 后续：评估薄入口
├── src/
│   ├── 开发规划与交付进度.md       # 本文，持续更新进度
│   ├── README.md                 # 后续：模块依赖与使用约定
│   ├── __init__.py               # 本地源码命名空间
│   └── pinn_sr/
│       ├── __init__.py
│       ├── cli.py                # 校验和流程编排
│       ├── config.py             # 参数、默认值、配置校验
│       ├── runtime.py            # 设备、精度、随机种子、环境信息
│       ├── data.py               # CSV 校验、数据结构、配点采样
│       ├── network.py            # MLP、初始化、归一化 buffers
│       ├── pinn.py               # 预测、三维 PDE 残差、损失项
│       ├── pinn_train.py         # 优化器、训练循环、续训调度
│       ├── checkpoint.py         # 状态保存、恢复、版本兼容
│       ├── experiment.py         # 实验目录、日志、来源指纹
│       ├── metrics.py            # 纯数值指标
│       ├── evaluation.py         # 后续：评估流程编排
│       └── visualization.py      # 后续：无界面绘图
├── tests/
└── docs/experiments/
```

模块单向依赖原则：入口负责调用；训练器组织数据、模型和保存；模型不反向导入训练器；评估器复用模型恢复和数值指标，不依赖训练循环。首轮物理方程留在 pinn.py，新增多种 PDE 时再考虑独立 physics/。

### 3.1 已实现的功能迁移表

| 重构前 train.py 中的内容 | 当前归属 | 拆分后的职责 |
| --- | --- | --- |
| make_parser、数值参数校验 | config.py | 返回配置并校验，不创建实验目录 |
| select_device、随机种子、synchronize、environment | runtime.py | 显式选择 CPU/CUDA，记录运行环境 |

| ConfigurablePINN、当前借用作者的 predict/loss_func | pinn.py | 独立实现同等预测、残差与损失，不再动态绑定作者方法 |
| 当前模型内部的 Adam、training | pinn_train.py | 优化器与训练状态归训练器管理 |
| save/read/build/restore_checkpoint | checkpoint.py | 推理恢复与续训恢复分开，严格校验状态 |
| resolve_path、slug、create_run_dir、write_json、来源哈希与日志 | experiment.py | 项目根路径、安全目录、唯一命名、可追溯记录 |
| evaluate_fit 中的指标计算 | metrics.py | MAE、RMSE、Relative L2；无绘图和文件副作用 |
| main | 根 train.py + 配置/训练模块 | 保留外部调用方式，仅组织流程 |

补充约束：

- src 正式运行代码不使用 load_author_classes、sys.modules 替换或临时修改作者模块导入行为；作者实现仅在对照测试中使用。
- 项目根路径使用统一定义，不能移动到 src 后把相对 data/、runs/ 错误解析成 src/data/、src/runs/。
- 导入方案须支持仓库根目录执行与其他工作目录使用绝对入口执行；已使用 src.pinn_sr 导入方式，不新增打包依赖；根脚本绝对路径调用已通过测试。
- 保持现有输入校验，包括零分母速度、非有限值、恒定坐标维度；不在重构中静默添加 epsilon 改变基线。

## 5. 关键风险：已有 checkpoint 必须继续可用

已有入口使用 `pinn-sr-state-v1`。重构不能要求用户为了画图或评估而重新进行 500000 步训练。

| 场景 | 兼容目标 | 必须检查 |
| --- | --- | --- |
| 新代码读取旧 v1 做预测 | 本批次必须支持并测试 | 网络结构、state_dict 键、归一化边界、精度、物理参数与预测一致 |
| 新代码继续旧 v1 训练 | 显式迁移后才允许 | 优化器、采样器、随机状态、步数与训练/数据兼容性 |
| 新代码生成的新 checkpoint | 保存后可独立恢复 | 版本、配置、边界、权重、优化器及随机状态完整 |
| 作者旧完整对象模型 | 与本入口 v1 区分 | 不默认开放不安全 pickle；确有需求再增加可信文件专用转换流程 |

具体要求：

1. 优先保留现有 state_dict 键与参数顺序；若确需调整，提供明确、可测试、带版本的映射，不用 strict=False 静默跳过权重。
2. 当前续训签名包含 source_sha256。源码拆分必然改变指纹，必须区分“来源追踪”和“算法/结构/数据兼容性”，不能直接删除所有续训检查或无条件放行。
3. 先验证 CPU 上旧权重恢复后的预测；服务器实际权重尚未在本地读取，取得用户指定文件后再记录实际验收结果。
4. 推理加载只需要模型状态与训练时边界；优化器状态仅在续训路径读取。
5. 同环境 CPU 的短训练断点连续性需要测试；跨设备、跨 PyTorch 版本不承诺逐位相同。
6. 如引入新格式，保留 v1 读取器并记录迁移来源；不覆盖历史 checkpoint。

### 5.1 本次实际兼容策略

- v1 的 state_dict 键和参数顺序不变；读取旧权重推理无需迁移开关，模型恢复不创建优化器。
- 新版普通续训继续严格比较维护源码哈希和方法契约；旧版续训仅接受 checkpoint.py 内已核验的三文件哈希组合，并要求 --allow-legacy-resume。
- 选项不能绕过未知源码、参数、数据或方法不匹配；迁移来源写入新运行的 resume_compatibility。
- 使用重构前代码实际生成的 float32/float64 × sequential/random 小型权重，验证了旧权重推理和 2→4 步续训；服务器实际 500000 步权重仍待核验。

## 6. 第二批次：evaluate.py 数值评估

前置条件：R4 通过，旧 checkpoint 已能独立推理。优先使用已有 Linux 权重，避免无必要重训。

### 6.1 输入、流程与输出

```text
指定旧 run 或 checkpoint + 明确的评价数据
                 ↓
恢复模型、训练时归一化边界与配置（不创建优化器）
                 ↓
分批推理 u/v/w/p
                 ↓
按坐标与分量计算指标，标记评价集性质
                 ↓
在新的 postprocess 子目录保存结果
```

| 内容 | 规划 |
| --- | --- |
| 输入参数 | checkpoint/run、评价数据路径、CPU/CUDA、推理批大小、输出位置/标签；正式参数名待实现时确定 |
| 默认评价 | u/v/w 分量及速度大小的 MAE、RMSE、Relative L2；明确公式、聚合方式与零范数处理 |
| 输出 | eval_config.json、eval_metrics.json、逐点预测 NPZ/CSV；文件名在实现时固化 |
| 逐点数据 | xyz、参考 u/v/w、预测 u/v/w、分量误差；p 只能作为无标签预测值，不能报告压力精度 |
| 来源记录 | checkpoint 路径/哈希、训练步数、评价数据哈希、配置与评价集类型 |
| 保存规则 | 独立 postprocess/<唯一标识>/ 或指定安全评价根目录，不覆盖训练 config/summary/metrics |
| 原则 | 不调用训练、不默认续训、不修改 checkpoint；普通速度推理使用 no_grad 并分批 |

评价边界：

- 使用训练保存的坐标/速度变换，不能在测试集重新拟合归一化范围。
- training-fit 与 independent-test 分别标记；5/20/100 不能仅因文件夹不同就认作相互独立，需检查坐标与标签来源及重叠。
- 没有独立体积真值时，不宣称三维全域重建精度已经验证。
- PDE 残差作为可选独立评估：需要坐标求导，不能包在 no_grad 中；物理残差小不等同于速度误差小。
- 数据有非零速度限制与单平面归一化问题时，复用训练边界并显式处理，不能偷偷更改评价定义。

验收：同一权重与数据的数值结果可复算；分批与整批预测在合理容差内一致；明确展示评价点数、重叠情况和指标定义；没有新增训练过程。

## 8. 后续实验与横向数据接入

完成评估和图片后，再决定下一轮科学实验，不用工程重构替代方法验证。

| 优先级 | 任务 | 启动条件 |
| --- | --- | --- |
| P0 | 评估已有 500000 步权重，形成数值与图片基线 | 可访问 checkpoint、配置和对应评价数据 |
| P1 | 稀疏观测比例与多随机种子对照 | 固定独立评价集、采样协议与预算；先核对作者各数据组关系 |
| P1 | 记录显存、耗时与精度，研究梯度失衡/冲突 | baseline 稳定；将优化方法作为单独实验变量 |
| P2 | 企业双截面 DAT 适配器 | 确认列含义、坐标/单位、同步关系、几何和物理模型；不擅自上传数据 |
| P2 | 三维体积/独立截面验证 | 获得相应真值或可验证的独立观测 |
| P2 | 时间序列与预测模型接入 | 确认真实物理时间、采样间隔、同步帧与预测目标后再设计回看窗口 |

企业多文件的编号不自动等于连续物理时间；只有截面观测不等于拥有体积真值。当前重构保持稳态空间任务，不预设这些条件已经满足。
